# 기술 구성과 작업 순서

## 실행 구조

```text
확장 아이콘 → background.ts (URL 검사)
→ Chrome Side Panel / sidepanel/main.tsx (React UI + 로컬 저장 연결)
→ App.tsx (전체 선택 → 문구 → 대상별 미리보기 → 확인)
→ Web Lock (사이트 내 동시 게시 방지)
→ tabs.connect Port → youtube.content.tsx (스캔 토큰 → 실제 DOM)
→ youtube.ts (입력 → 게시 직전 이력 저장 → 클릭 → 새 답글 확인)
→ history.ts (posting / posted / uncertain 기록)
```

UI는 WXT + React + TypeScript, UI는 크롬 기본 Side Panel에 두고 DOM 조작은 콘텐츠 스크립트에서 수행합니다. 페이지에 패널·iframe을 삽입하거나 body 크기를 변경하지 않습니다. 별도 서버나 API 키는 없고 로그인한 사용자의 브라우저 안에서 실행합니다. WXT가 `.output/chrome-mv3/manifest.json`을 생성합니다.

## 주요 모듈

| 파일 | 역할 |
| --- | --- |
| `src/App.tsx` | 전체·개별 선택, 검토 시 대상·문구 스냅샷, 실행·중단·결과 |
| `src/reply-template.ts` | `{닉네임}` plain text 치환, 알 수 없는 변수 거부 |
| `src/youtube.ts` | 댓글 인식, 안정 식별키, 입력·버튼 조작, 새 답글 DOM 확인 |
| `src/history.ts` | 로컬 게시 상태 타입·검증 |
| `entrypoints/sidepanel/main.tsx` | 영상 탭에 연결한 사이드 패널 부팅·재연결 |
| `src/controller.ts` | 영상 탭과 Port RPC, 연결 해제·중단 전달 |
| `entrypoints/youtube.content.tsx` | DOM 대상 보관·검증·게시·Port 종료 시 중단 |
| `src/storage.ts` | 문구와 게시 이력 저장소 |
| `entrypoints/background.ts` | 사용자가 확장 아이콘을 누른 탭에만 주입 |
| `public/fixtures` | 외부 전송 없는 모의 화면·게시 결과·실패 사례 |

## 대상·문구 확정

댓글 읽기 시 현재 로딩된 최상위 댓글을 수집하고 이력이 없는 대상을 전체 선택합니다. 아직 로딩되지 않은 댓글을 수집 완료로 표시하지 않습니다. 검토 단계에서 대상과 닉네임 치환 결과를 복사해 고정합니다. 문구·선택 변경은 검토를 무효화하고 다시 확인받습니다. SPA 영상 이동 시 작업 중단을 요청하고 대상을 비웁니다.

`{닉네임}`은 표시 이름의 앞 @를 제거한 텍스트이며 실제 멘션이 아닙니다. `textContent`를 사용해 이름·링크·특수문자를 HTML로 실행하지 않습니다.

## 게시와 불확실성

게시 전 댓글 연결 상태·영상·작성자·본문과 비어 있거나 확정한 문구와 정확히 일치하는 입력란을 확인합니다. 입력 후 게시 버튼이 활성화되어야 진행합니다. 클릭 직전에 로컬 `posting` 기록을 저장하고, 저장에 실패하면 클릭하지 않습니다. 새로 생성된 답글 요소에서 `img.alt`와 줄바꿈을 포함한 표시 본문을 읽고 동일 본문을 확인해야 `posted`로 바꿉니다. 입력란이 비었다는 이유만으로 성공 처리하지 않습니다.

게시 결과가 불분명하거나 클릭 이후 화면이 바뀌면 `uncertain`으로 기록하고 멈춥니다. 다음 대상 자동 진행과 자동 재시도는 하지 않습니다. 재로딩 후 `posting`도 재게시에서 제외합니다. 이력은 동일 브라우저 프로필에 한정되며 정확히 한 번 전달을 전역적으로 보장하지 않습니다. 현재 화면 외 수동 안내 여부도 자동 추정하지 않습니다.

중단 버튼은 다음 게시를 막으며 이미 클릭한 게시를 취소하지 않습니다. 검토 후 실행은 입력에서 끝나지 않고 게시 버튼 클릭까지 수행합니다. 정확히 같은 문구가 이미 입력돼 있으면 재사용하고, 게시 버튼의 비동기 활성화를 기다립니다. 다른 초안은 보존합니다. 같은 확장의 사이드 패널들은 확장 origin의 Web Locks로 실행을 직렬화하고 잠금 획득 후 로컬 이력을 다시 읽습니다.

## 식별과 개인정보

영상 ID + 댓글 ID를 우선 사용하고 불가능하면 작성자 링크·원문 지문으로 보수적으로 중복을 판단합니다. 저장 값에는 해시 식별키·상태·시각만 포함합니다. 댓글 원문과 작성자명은 현재 페이지 메모리에서만 사용합니다. 해시는 익명성 보장을 뜻하지 않으며 로컬 데이터 역시 접근 가능한 사용자에게 노출될 수 있습니다.

## 작업 순서

환경 → DOM 어댑터 → 단일 입력 검증 → 전체 선택·닉네임 → 게시 검토 → 로컬 이력·중단·결과 불확실 처리 → 통합·접근성 검증 → 실제 유튜브 수동 검증.

실제 유튜브에서는 DOM 위치·contenteditable 상태 반영·게시 결과 표시가 다를 수 있습니다. 플랫폼이 명시적으로 허용한 운영 방식인지도 별도로 확인해야 합니다.

## 삭제 후 재게시

사용자가 해당 댓글에서 재게시 허용과 이력 해제 확인을 누르면 동일한 Web Lock 안에서 그 댓글의 이력만 제거합니다. 대상은 다시 선택하지만 자동으로 전송하지 않으며 검토 과정을 다시 거칩니다. 이력 해제 확인 화면을 열거나 취소하는 것만으로는 이력을 변경하지 않습니다. `posting`·`uncertain`도 직접 결과 확인 후 해제할 수 있습니다. 접힌 답글·미로딩 상태를 삭제로 오인하지 않도록 DOM에서 답글이 보이지 않는 것만으로 이력을 지우지 않습니다.

## 연결 수명

`background.ts`는 `openPanelOnActionClick: false`로 기본 열기를 끄고 `action.onClicked`를 등록합니다. 아이콘 클릭으로 activeTab을 확보하고 이벤트 핸들러에서 `sidePanel.open({ windowId })`을 즉시 호출합니다. `open()` 전에 비동기 작업을 기다리지 않습니다. 열린 뒤 같은 창의 패널에 재연결을 알립니다. `sidepanel/main.tsx`의 scan이 활성 탭의 주소를 검증하고 activeTab으로 콘텐츠 스크립트를 주입한 뒤 연결·수집합니다. 이전 탭별 패널 경로의 tabId 쿼리도 호환합니다. 페이지에 React나 키보드 전역 리스너를 주입하지 않습니다.

스캔 시 DOM 대상은 콘텐츠 스크립트에 남기고 임시 토큰을 패널로 전달합니다. 토큰은 스캔마다 갱신되며 콘텐츠 스크립트는 게시 직전 DOM 연결·영상·작성자·본문을 검증합니다. 패널은 배치 전체 동안 확장 origin Web Lock을 유지합니다. 게시 전 `posting` 기록과 실제 클릭은 콘텐츠 스크립트에서 순서대로 수행하므로 UI 연결이 끊겨도 중복 방지 이력은 남습니다. 연결 종료 시 해당 포트의 AbortController를 중단하고 결과가 불분명하면 `uncertain`으로 기록합니다.

영상 새로고침 후 댓글 읽기를 누르면 UI가 새 DOM 연결을 주입하고 댓글까지 수집합니다. 전역 패널에서 영상 탭 전환을 감지하면 기존 연결을 종료하고 사용자가 새 대상을 연결하도록 안내합니다. 재연결하면 기존 선택·검토는 버립니다. 닫힌 브라우저에서 배치를 지속하는 서버 작업은 없습니다.

## 유튜브 본문과 중첩 답글

`readCommentText`는 텍스트 노드·이미지 alt·br을 순서대로 읽습니다. 유튜브가 Unicode 이모지를 이미지로 대체하면 textContent에는 이모지가 없으므로 textContent만 비교해서는 안 됩니다. 완료 확인에서는 NFC·공백·이모지 표시 선택자만 정규화하고 서로 다른 이모지는 유지합니다. 원댓글 스캔은 다른 thread 아래의 중첩 thread를 제외합니다. 게시 결과 불명확 상태의 중단 동작은 유지합니다.

## 읽기 요청과 쇼츠 패널

안정된 Controller 파사드를 App에 전달하고 scan마다 실제 Port를 새로 연결합니다. App은 다시 마운트하지 않아 미저장 문구를 유지합니다. 읽기 시작 시 이전 대상·선택·검토를 지우고 중복 읽기를 막습니다. 읽기 세대가 달라진 이전 identity 응답은 무시합니다. 탭 전환·연결 해제 시 진행 중 스캔도 중단합니다.

콘텐츠 스크립트는 쇼츠에서 열린 댓글 패널을 먼저 확인합니다. 닫힌 경우 뷰포트에 있는 댓글 버튼 하나만 클릭하고 패널과 댓글 로딩을 기다립니다. 댓글 버튼이 없거나 비활성·시간 초과·영상 변경이면 이유를 반환합니다. 이미 열린 패널은 토글하지 않습니다. 일반 영상에서는 이 단계를 건너뜁니다.
