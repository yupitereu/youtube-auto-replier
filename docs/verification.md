## 0.3.1 실환경 진단

실제 크롬 `chrome://extensions`에서 도우미의 설치 경로가 `.output/chrome-mv3`임을 확인했지만, 로드된 Manifest 버전은 `0.1.0`으로 표시됐습니다. 파일 빌드와 확장 새로고침은 별개입니다. 이 조합은 초기 백그라운드가 UI를 표시하지 않는 새 콘텐츠 스크립트를 호출하는 상태를 만들 수 있습니다. 확장 카드를 새로고침해 Manifest·권한·백그라운드를 함께 업데이트해야 합니다.

추가로 0.3.0의 `setOptions` await 이후 `open` 순서는 사용자 활성화가 소실될 수 있습니다. 0.3.1에서는 해당 호출을 없애고 Chrome 기본 아이콘 동작으로 열도록 수정했습니다. 실제 크롬 확장 세부정보의 새로고침 버튼으로 0.3.1 적용을 확인했고, 네이티브 사이드 패널에 LOCAL PROTOTYPE · 0.3.1과 연결 재시도 화면이 표시되는 것까지 확인했습니다. 영상 탭 접근·연결 완료와 실제 게시의 실환경 확인은 이번 변경에서 수행하지 않았습니다.

## 0.3.2 실환경 연결 검증

0.3.1 패널이 열린 상태에서도 유튜브 영상 주소를 읽지 못했고, Chrome 툴바에 해당 사이트 접근 권한이 필요하다고 표시됐습니다. 기본 패널 열기 대신 `action.onClicked`에서 activeTab을 확보하고 즉시 `sidePanel.open`을 호출하도록 수정했습니다. `setOptions`나 비동기 조회를 먼저 하지 않습니다. 권한이 없는 상태는 지원하지 않는 URL과 별도 오류로 구분합니다.

실제 크롬의 확장 새로고침으로 버전 0.3.2 적용을 확인했습니다. 사용자가 열어둔 유튜브 쇼츠에서 도우미 툴바 아이콘을 클릭한 뒤 사이트 접근 권한이 활성화된 상태와 정상 도우미 UI를 확인했습니다. 이어서 댓글 읽기를 눌러 현재 로딩된 원댓글 **7개**와 기존 게시 이력이 패널에 표시되는 것을 확인했습니다. 이 검증에서 새 답글은 게시하지 않았습니다.

## 0.3.3 첫 게시 뒤 중단 진단

실제 패널에는 5개 대상 중 0건 확인 후 ‘새 답글을 화면에서 확인하지 못했습니다’라는 중단 사유가 남아 있었습니다. 실제 게시된 본문 DOM에서 🎉가 img.alt로 표현되고 textContent에서 빠지는 것을 확인했습니다. 확장의 문자열 비교가 실패해 첫 게시 뒤 안전 중단한 원인입니다. 동시에 펼쳐진 답글에 중첩된 ytd-comment-thread-renderer가 있어 기존 스캔이 이를 원댓글로 잘못 포함하는 것도 확인했습니다.

해당 DOM 표현을 로컬 모의 화면에 반영한 5건 순차 게시 회귀 시나리오가 통과했습니다. 실제 유튜브에서 추가 답글을 보내는 검증은 수행하지 않았습니다. 기존 uncertain 이력은 자동 초기화하지 않습니다.

## 0.3.4 화면 문구

확장 이름·툴바 제목·사이드 패널 제목을 유튜브 답글 도우미로 통일했습니다. 사용자 화면과 Manifest에서 프로토타입 표시를 제거하고 버전만 표시합니다. 재게시 허용은 게시 이력만 해제하는 기능임을 설명하고, 확인 버튼은 이력 해제하고 다시 선택으로 변경했습니다. 기존 답글을 삭제하거나 즉시 재게시하지 않는 흐름은 유지합니다. 설치 폴더는 확장 ID와 저장 이력을 보존하도록 변경하지 않습니다.

## 0.3.5 읽기와 연결 통합

다시 연결과 연결 재시도 버튼을 제거했습니다. App을 유지한 채 댓글 읽기 요청마다 현재 영상·스크립트·Port를 갱신하므로 저장하지 않은 문구도 보존됩니다. 영상 연결 끊김 감지는 이전 목록과 검토를 무효화하고 같은 댓글 읽기 버튼으로 복구하도록 안내합니다. 로딩 중에는 이전 연결의 폴링 응답이 새 읽기 결과를 덮어쓰지 않게 세대를 구분합니다.

실제 쇼츠 화면에서 댓글 버튼의 접근성 이름·위치와 engagement-panel-comments-section 패널의 visibility 속성을 확인해 자동 열기를 구현했습니다. 로컬 모의 화면에 같은 구조·지연 로딩·비활성 버튼을 반영해 검증합니다.

## 0.3.6 문구 정리

현재 댓글 읽기 위의 소개·자동 등록 설명·공개 게시 안내를 제거해 첫 작업부터 표시합니다. 두 번째 제목은 답글 내용으로 변경했습니다. 이번 변경은 화면 문구만 수정했으며 타입 검사와 빌드로 확인했습니다. 위 23개 브라우저 시나리오의 실행 결과는 0.3.5 기준입니다.

## 0.3.7 입력 흐름 정리

첫 단계는 댓글 선택, 둘째 단계는 답글 내용 입력으로 표시합니다. 댓글 읽기 버튼은 제목 영역 오른쪽으로 옮겼습니다. textarea는 보이는 중복 라벨 없이 제목을 aria-labelledby로 참조합니다. 닉네임 추가는 textarea의 선택 범위에 삽입하고, 렌더 후 포커스와 커서를 삽입한 토큰 뒤로 복원합니다. 같은 토큰을 같은 토큰으로 교체해 값이 바뀌지 않는 경우와 키보드 실행도 포함해 브라우저에서 검증합니다.

## 0.3.8 안내 문구

댓글 선택 영역은 답글을 등록할 댓글을 선택하세요로 간결하게 안내합니다. 추가 댓글을 읽는 방법은 제목 영역의 댓글 읽기 버튼 근처에 표시하고 aria-describedby로 연결했습니다. 문구와 배치 변경은 타입 검사·빌드로 확인하며, 위 브라우저 테스트 24개는 0.3.7 실행 결과입니다.

## 0.3.9 댓글 읽기 강조

제목 영역의 댓글 읽기 버튼에 진한 녹색 배경·흰 글씨·굵은 글씨·46px 최소 높이와 hover/active 상태를 적용했습니다. 타입 검사와 빌드를 통과했고, 좁은 화면·키보드·axe 접근성 시나리오 1개를 다시 실행해 통과했습니다. 전체 24개 실행 결과는 0.3.7 기준입니다.

## 0.3.10 설명 정리

검토 단계의 내부 처리 순서 설명을 제거해 제목에서 검토 버튼으로 바로 이어지도록 정리했습니다. 화면 문구 변경은 타입 검사와 빌드로 확인했습니다.

## 0.3.11 검토 문구

미리보기에서 답글로 용어를 통일하고 확인 문구를 선택한 댓글과 답글 내용을 확인했습니다로 변경했습니다. 타입 검사와 빌드로 확인했습니다.

## 0.3.12 등록 중 안내

실제 등록 작업 동안 sticky header에 고대비 안내를 role=alert로 표시합니다. 재게시 이력 해제 시에는 표시하지 않습니다. 댓글 추가 읽기 안내 대신 등록 중 주의사항을 보여주고, 완료·중단 후 원래 안내로 복원합니다. 쇼츠 댓글 패널 닫힘을 구분해 게시 전이면 중단 이유를, 게시 시도 후면 결과 불확실 안내를 반환합니다.

## 0.3.14 현재 상태 위치

현재 상태를 하단에서 상단 sticky header로 옮겼습니다. 스크롤 후에도 완료 안내가 뷰포트 안에 있는지 확인하는 검증을 추가했습니다. 타입 검사·빌드와 좁은 화면/접근성·등록 안내 시나리오 2개를 실행해 통과했습니다. 전체 26개 실행 결과는 0.3.12 기준입니다.

## 0.3.15 안내 패널 통합

현재 상태 라벨과 별도 경고 패널을 제거했습니다. 상단 안내 패널 하나에 상태와 경고를 함께 표시하며 등록 중에만 황색 배경·진한 테두리를 적용합니다. 경고는 답글 등록이 끝날 때까지 유튜브 댓글 창과 확장 프로그램을 닫지 마세요로 변경했습니다. 타입 검사·빌드와 좁은 화면 및 등록 완료/중단 시나리오 3개를 확인했습니다.

## 0.3.16 로고

SVG 원본과 16·32·48·128·512px PNG를 생성하고 툴바·확장 정보·패널 제목에 적용했습니다. 타입 검사·빌드와 좁은 화면 접근성 시나리오 1개가 통과했습니다. 빌드 Manifest의 아이콘 경로와 실제 PNG 크기가 일치하는지도 확인했습니다.

## 0.3.17 로고 색상과 표시

빨간색 말풍선에 재생 삼각형과 답글 화살표 배지를 조합했습니다. SVG와 모든 PNG 크기를 다시 생성했고 타입 검사와 빌드로 확인했습니다.

## 0.3.18 하단 정리

버전은 제목 영역에서 최하단으로 옮겨 작게 표시하고, 결과 확인에 관한 고정 하단 안내를 제거했습니다. 실제 완료·중단 사유와 등록 중 경고는 상단 패널에서 계속 안내합니다. 타입 검사와 빌드로 확인했습니다. 버튼의 녹색은 CSS 고정값이며 크롬 테마에서 가져오는 색이 아닙니다.
